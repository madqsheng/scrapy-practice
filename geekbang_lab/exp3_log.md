# 实验3 记录

## 目的
控制变量 `size` 与 `prev`，验证：固定 `product_type=0, pvip=0, with_articles=false` 时，用 `size=10` 分 5 页（prev=0/10/20/30/40）拼起来的结果，是否恰好等于实验1 第一组（`size=50, prev=0`，返回 50 门）的完整集合。从而确认 `prev` 是数量偏移、`size` 是本页条数、列表顺序可拼接。

## 接口
主接口（唯一使用）：`https://time.geekbang.org/serv/v4/pvip/product_list`
不使用 `serv/v3/learn/product`（已弃用，不备份）。

## 唯一变量
`size` 与 `prev`：五组均为 `size=10`，`prev` 取 0/10/20/30/40

## 固定参数（其余不变）
- `product_type`: 0
- `pvip`: 0
- `with_articles`: false
- `tag_ids`: []
- `product_form`: 0
- `sort`: 8

## 五个请求定义
1. `size=10`, `prev=0`（取第 1–10 条）
2. `size=10`, `prev=10`（取第 11–20 条）
3. `size=10`, `prev=20`（取第 21–30 条）
4. `size=10`, `prev=30`（取第 31–40 条）
5. `size=10`, `prev=40`（取第 41–50 条）

## 执行方式
- 前台执行（非后台），边执行边保存
- 每请求间隔 4 秒，控节奏防 cookie 限额
- 走代理 `127.0.0.1:7897`
- 使用新 cookie（`geekbang_lab/.cookie.txt`）
- 每个请求完成立即写入 `exp3_raw.json`，不写任何结论

## 产物
- `exp3_raw.json`：5 个请求的 URL + 负载 + 完整响应（`data.products`），原始数据，无结论
- 本文件：仅记录实验设计 / 过程

## 原始计数（非结论）
- group1 `size=10 prev=0` → HTTP 200，返回 10 门
- group2 `size=10 prev=10` → HTTP 200，返回 10 门
- group3 `size=10 prev=20` → HTTP 200，返回 10 门
- group4 `size=10 prev=30` → HTTP 200，返回 10 门
- group5 `size=10 prev=40` → HTTP 200，返回 10 门
- 合计 5×10 = 50 门，与实验1 第一组（`size=50 prev=0`，返回 50 门）计数吻合
- 注：计数吻合**不代表集合相等**。需用 id 集合对比「exp3 五组合并」与「exp1 第一组」是否完全一致（顺序稳定、无重叠、无缺失），才算验证成功。

## 对照验证结果（实测，已证伪原假设）

**方法**：提取各请求 `response.data.products[].id`；实验3 按组序（prev=0→40）拼接 id 列表，与实验1 第一组（`size=50, prev=0`）的 id 列表做「逐条顺序比对」+「集合比对」。

**实测数据**：
- 实验1 第一组：50 条
- 实验3 五组拼接：50 条
- 两者**集合不相等**：交集仅 **10** 条；实验1 独有 **40** 条，实验3 独有 **40** 条
- 顺序逐条比对：从**位置 10** 起全部错位（位置 0–9 完全一致，即仅 `prev=0` 那一组对得上）
- 内部重复：两组各自无重复 id

**结论**：
- ❌ 原假设「五组(size=10,prev=0/10/20/30/40) 拼接 == 实验1 第一组(size=50,prev=0)」**不成立**。
- ❌ 「prev 是数量偏移、可任意切页拼接」的假设**被推翻（至少跨 size 时不成立）**。

**暴露的根因（待定，需额外实验定性，非本实验结论）**：
1. `prev` 可能不是绝对数量偏移，而是服务端游标（cursor），不同 size 下游标语义分裂；
2. 或列表排序随 `size` 变化（`prev=0` 前两条碰巧一致，`prev=10` 后窗口指向了不同数据）。

**对扫全量的影响**：后续必须**固定单一 size 连续翻页**，不能混用 size；`prev` 步进方式需重新验证（建议用同 size 的两页拼接自洽性实验来定性）。
