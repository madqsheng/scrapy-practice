极客时间爬虫 jk · 使用说明

一份可长期复用的上手文档。覆盖四种模式的使用命令、各自独立的请求链路（含流程图），以及增量续爬与排查要点。

一、总览

项目：jikeshijian/ 是一个 Scrapy 项目，蜘蛛名为 jk，用来把极客时间课程的文章正文 + 评论按课程归档成 HTML 落到本地。

四种模式（同一个蜘蛛，靠参数 / 配置切换）：

模式触发方式做什么
① 全量MY_COURSES=[]
或 scrapy crawl jk		爬「我的课程」里全部已买课程
② 指定课程MY_COURSES 或 -a courses= / -a course_ids=只爬你点名的几门课（课名离线解析成 id）
③ 数量-a limit=N爬「我的课程」里前 N 门
④ 重建索引-a rebuild_index=1重新抓取课程目录，从零重写 course_index.json

优先级：-a courses > -a limit > MY_COURSES > 全部。辅助：-a course_ids=（直接给 id）、-a force=1（强制重爬）。

二、运行前准备

  • Python：用受管运行时（不要裸 python）
    C:/Users/admin/.workbuddy/binaries/python/versions/3.13.12/python.exe
  • Cookie：编辑 jikeshijian/jikeshijian/settings.py 里的 MY_COOKIE，整串粘贴新 cookie。爬虫与重建索引共用这一处。
  • 代理：翻页请求走系统/环境变量里的代理（默认 127.0.0.1:7897）。爬之前确认代理开着，否则请求会因区域被拦。
  • 节流：默认每门课程之间 SLEEP_BETWEEN=2s；重建索引模式每页 3s。不要在代理不稳时拉高并发。
  • 落盘位置：jikeshijian/resource/jikeshijian/<课程名>/<文章标题>.html
  • ffmpeg（视频课必需）：爬视频课（如《AI Agent智能体实战课》《DeepSeek Harness 极简入门》）时，爬虫会走 video_play_auth → GetPlayInfo 拿到阿里云加密 HLS（m3u8），再用 ffmpeg 把分片解密合并成离线可看的 mp4。代码会自动定位 ffmpeg：优先 PATH → 环境变量 FFMPEG_BIN → 常见自带目录（剪映 JianyingPro、Krita、conda 等，版本无关通配）。多数机器（装过剪映/Krita）其实已经有真 ffmpeg，不用专门安装；实在找不到时，可设 FFMPEG_BIN 指向其绝对路径，或把 ffmpeg 加入 PATH。注意：pip install ffmpeg 装的是空壳封装、不含真二进制，没用。GetPlayInfo 请求走的是 vod.cn-shanghai.aliyuncs.com，已被 spider 的 allowed_domains 放行；若自行改代码务必别漏掉这个域名，否则视频链路会被离站中间件静默丢弃。

三、四种模式命令（简化版）

① 全量

scrapy crawl jk

前提：settings.py 里 MY_COURSES = []。爬你购买的全部课程，不看索引。

② 指定课程

# 方式 A：改配置后跑
#   MY_COURSES = ["生产级 Agent 排雷实战", "DeepSeek Harness 极简入门"]
scrapy crawl jk

# 方式 B：命令行临时指定课名
scrapy crawl jk -a courses="生产级 Agent 排雷实战,DeepSeek Harness 极简入门"

# 方式 C：直接给课程 id（绕过课名解析）
scrapy crawl jk -a course_ids="101170001,101128701"

A/B 走「课名 → 离线索引 id」解析；C 直接用 id。

③ 数量

scrapy crawl jk -a limit=3

爬「我的课程」里前 3 门（顺序由 learn/product 返回决定）。

④ 重建索引

scrapy crawl jk -a rebuild_index=1

从零重写 course_index.json。跑之前先更新 MY_COOKIE。

所有模式都可在末尾追加 -a force=1 强制全量重爬（忽略本地已存 HTML 的增量跳过）。

四、四种模式请求链路（详细 + 图示）

下面四种模式分开画清楚：每个模式先发哪个请求、做了什么、下一个请求又做什么，直到最后落盘。模式 ①/②/③ 在「拿到课程 id 之后」共用同一条「内容爬取链路」（见末尾）。

① 全量 请求链路

模式①：只看「我的课程」，不碰离线索引、不查 product_list 目录。

逐请求说明

  • ① POST serv/v3/learn/product：负载 {"data":{"ctype":1,"page":1,...}}。返回你账号下已购/可看课程。响应分页，靠 page_count 翻到底。
  • ①' parse_product：把每一页的课程塞进 self._products 跨页累加，直到最后一页。
  • _finalize → _get_wanted：因 MY_COURSES=[] 且无 courses/limit，wanted = 全部课程，直接进内容爬取。
  • 之后走「通用内容爬取链路」（第四节末尾）。

② 指定课程 请求链路

模式②：先收齐「我的课程」，再用离线索引把课名解析成 id；索引里没有才回退查目录，再没有就跳过。

逐请求说明

  • ① POST serv/v3/learn/product：同模式①，先翻页收齐「我的课程」列表（这一步是为了后面按 id 取文章，也作为索引缺失时的备选）。
  • ② 离线索引解析：读 course_index.json 的 by_title（当前约 534 门），把命令行 / MY_COURSES 里的课名做精确匹配得到课程 id。不发任何网络查目录请求，稳且不触发限流。-a course_ids= 给的 id 直接进 wanted，不查索引。
  • ③ 缺失回退：若某课名在索引里查不到，才发 POST serv/v4/pvip/product_list 在目录里搜索一次做补救。
  • 搜不到：索引 + 目录都找不到 → 打印 WARNING 并跳过该课（不会中断整个任务）。补救办法：把课程页 id 填进 MY_COURSE_IDS 或用 -a course_ids=。
  • 命中后走「通用内容爬取链路」。
索引只覆盖 product_type=0 + pvip=0（约 534 门）。其它类型 / pvip=1 / 个别 VIP 新课不在里面，指定模式下会跳过——这是预期，不是 bug。

③ 数量 请求链路

模式③：等价于「先全量收齐，再只取前 N 门」，前面部分和模式①完全一致。

逐请求说明

  • ① POST serv/v3/learn/product：同模式①，翻页收齐全部「我的课程」。
  • ①' parse_product：跨页累加。
  • _get_wanted 截断：wanted = 课程列表的前 N 门。N 来自 -a limit=N。
  • 之后走「通用内容爬取链路」。

④ 重建索引 请求链路

模式④：直接打目录接口翻页，不爬文章内容，目的是重建「课程名↔id」离线映射。

逐请求说明

  • ① POST serv/v4/pvip/product_list：负载 {"tag_ids":[],"product_form":0,"product_type":0,"pvip":0,"prev":0,"size":20,"sort":8,"with_articles":false}。prev 是页索引语义（你浏览器实测的规律），从 0 开始每次 +1。
  • ② parse_rebuild_index：从响应 data.products 取每项 id（值）+ title（键）。注意取 products 而非 list（list 只有 product_id 没 title）。
  • ③ 边存：每解析完一页就写入 course_index.json 的 by_title，断点也不丢。
  • ④ 停止条件（三选一即停）：服务器返回 more=False；连续 3 页「新增为 0」；prev ≥ 60。
  • ⑤ 落盘：结束时写 {"updated_at":...,"total":N,"by_title":{...}} 覆盖原文件（纯一一对应，无 extra 双字段）。
  • 自带 await asyncio.sleep(3) 节流，防限额。Cookie 由 MY_COOKIE 注入，请求带 Referer/Origin/Accept 避 451。
当前只扫 product_type=0 + pvip=0，实测得到约 534 门（page.total=560 是跨所有类型的全局数，不是这一组合的真实条数）。要更接近 560+ 需并集 pvip=1/其它类型——会突破当前前提，需另行确认。

通用内容爬取链路（模式 ①/②/③ 拿到课程 id 后共用）

三种爬取模式在「拿到课程 id」之后，都走这条相同的内容链路，把正文和评论存成 HTML。

逐请求说明

  • ① POST serv/v1/column/articles：负载带课程 id，返回该课所有文章（标题、article_id、是否免费等）。
  • ② 遍历 + 增量跳过：对每篇文章，检查本地是否已有 <课程>/<文章>.html。已存在且非 force 模式 → 跳过（这就是续爬能力）；不存在 → 继续。
  • ③ POST serv/v1/article：取文章正文，返回 HTML 片段。
  • ④ POST serv/v4/comment/list：取评论，先 sort=0（按热度）再 sort=1（按时间）两次请求合并，覆盖更全。
  • ⑤ 落盘：正文 + 评论合成一个 HTML，写入 resource/jikeshijian/<课程名>/<文章标题>.html。

五、增量 / 续爬

  • 默认即增量：每篇文章先比对本地已存 HTML，存在就跳过。课程没更完、或上次中断，再跑同一条命令会自动「续上」。
  • 强制全量重爬：追加 -a force=1，忽略本地已存，全部重新抓取（用于课程大更新或本地文件损坏）。
  • 结束汇总：爬虫结束时打印本次爬取/跳过/新增数量，一眼确认是「续上了」还是「全量重爬了」。
关键误区：scrapy crawl jk 是增量模式，但增量 =「本地有就跳过」，不是「检查并自动更新」。跳过判断在抓取文章之前就发生（jk_article.py 里 os.path.exists 命中即 continue），命中后连服务器请求都不发，更不会进 pipeline 重新渲染。所以改了 pipelines.py 的 HTML 模板 / JS 后，已存文件不会自动刷新——必须主动触发重渲。

改模板 / JS 后，如何让存量文章吃到更新

阅读页体验（图片灯箱、图注、评论「最新/精选」切换等）都写在 pipelines.py 的模板里。模板只在文章被重新渲染时生成新 HTML；增量模式把已存文章全跳过，新模板没机会跑。想让已落盘的文章也恢复这些交互，必须让它「重新渲染」——即加 -a force=1 关掉跳过逻辑。

两种等价命令

命令重渲范围请求量 / 风险
scrapy crawl jk -a force=1MY_COURSES 配置的那批（当前 12 门）大，易撞 452 限流
scrapy crawl jk -a courses="A,B" -a force=1只重渲点名的几门小，更安全
  • 前提：force=1 是真去服务器重新拉文章，需要 settings.MY_COOKIE 为最新有效 cookie + 代理开着，否则会 451/452 失败。
  • 范围建议：先用 -a courses="..." 只挑「确实有图片/图注/评论」的课来强刷，范围最小、最不易触发限额；确认没问题再决定是否全量。
  • 一句话区分：不加 force → 只补「缺失」文章；加 force=1 → 重渲「已存」文章。要让模板修复落到存量文件，就必须加 force。

六、排查表

现象原因 / 处理
请求返回 451缺 Referer/Origin/Accept 头（重建模式已内置）；常规爬取由中间件注入，一般不出。
请求被区域拦截 / 空响应代理没开。确认 127.0.0.1:7897 可用，环境变量里有代理。
指定课程被跳过 + WARNING课名在 course_index.json 索引里没有。改用 -a course_ids= 直接给 id，或把 id 填进 MY_COURSE_IDS。
重建索引不是 560 而是 534正常。product_type=0+pvip=0 真实只有 534；page.total=560 是跨所有类型的全局数。
增量没续上、全重爬了可能加了 -a force=1；或本地 HTML 路径/文件名变了导致比对失败。
改了 pipelines.py 模板，已存 HTML 没变增量模式跳过了已存文件。要让模板修复落到存量，加 -a force=1（建议配合 -a courses= 缩小范围）。
Cookie 失效（大量 401/空）更新 settings.py 的 MY_COOKIE，重建索引同样吃这一处。
视频课文章生成了，但点开没有视频 / 视频打不开多半是没装 ffmpeg，或当初是增量跳过没触发视频下载。装好 ffmpeg 后，对该课加 -a force=1 重跑一次即可补下 mp4（HTML 里已预留 视频/<标题>.mp4 引用）。
视频下载报错 / 日志提示「视频下载失败」阿里云 STS 令牌约 4 分钟过期，video_play_auth → GetPlayInfo → 下载 必须在同一次爬取内连完（代码已保证）；失败多为网络/代理或 ffmpeg 缺失，看具体报错。
